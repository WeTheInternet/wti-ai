# Report workflow to project history

During an active assignment, compare the milestone with the last accepted record. Reuse a standing publication grant within its named scope. Skip duplicate reports, routine messages and heartbeats.

1. Read the companion repository's instructions on main. Resolve the enrolled project, opted-in stable actor, sole writer, exact repository and full ref, allowed paths, and approved transport from the assignment. The WTI-AI convention uses a private `<code-repo>-history` companion and `refs/heads/agents/<stable-id>`. Confirm the actual destination from the assignment. The instructions branch holds shared conventions. A missing binding calls for a private draft and a precise handoff to the assignment owner.
2. Read the current agent record at an immutable tip. Reconcile any pending or uncertain attempt first. Capture the changed effort, owner, reported state, blocker and who can act, next action, UTC report time when known, and evidence at an immutable revision. Attribute an owner statement to its author and credit a relay separately. Use project-role identifiers. Exclude transcripts, personal information and credentials.
3. Update the branch's `ACTIVE.md` for the changed effort. Archive a completed effort only when worth retaining, and link it from the active record. Keep an already-current prose record. For an authorized Graph projection, prepare a separate commit changing only `status/summary.json`. Feed the exact candidate bytes to the project's actual decoder and check the decoded IDs, time, status and attribution. Keep additional provenance in the prose or commit when the schema lacks fields. If a required time or attribution is unknown and the writer requires it, checkpoint the gap instead of guessing.
4. Use the approved single-writer route. Review the exact diff, pin the expected parent, and publish a fast-forward update to the assigned ref. Verify the destination after each commit before basing another commit on it. For the WTI-AI local writer, follow the writer instructions supplied with the assigned code revision. It accepts only a preassigned local bare destination. A hosted branch requires its own authorized hosted route. Leave credentials to the connection provider.
5. From a fresh destination read, compare the observed tip with the submitted full commit and verify the path's bytes and SHA-256. If the ref moved or the outcome is uncertain, preserve the attempt and reconcile before retrying. Record a private receipt with actor, publisher, repo/ref/path, previous and submitted tip, observed tip, digest, and report time. Deliver it via the established reader handoff. Claim independent verification only after a separate reader supplies its own exact-commit result.
